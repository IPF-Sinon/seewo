# 对 DeepSeek 对话内容的勘误与实证结论

> 本文对用户提供的 DeepSeek 对话（"两份tasklist差异"）中的技术结论做**逐条实证核对**。
> 核对依据：本机解包的真实产物 `.work/app/main.js`（希沃管家 v1.2.7）与 `.work/app/public/screensaver.js`。
> **标注 [实证] 的结论均已在真实代码上验证；标注 [勘误] 的是原对话有误或含义不清之处。**

## 二、最重要的勘误：`this.startLock is not a function` 的真正根因

原对话说这是"希沃这个版本在屏保转锁屏的衔接上有 Bug"，说法**方向对但归因不准确**——
它真实原因是**一段写死的代码作用域错误**，而不是偶发缺陷。

### [实证] 证据链

**① 窗口管理器（webpack module 69）的 close 回调：**
```js
r.on("close", () => { setTimeout(() => { this.closeWindow(), this.startLock() }, 0) })
//                                                              ^^^^^^^^^^^^ 调用点
```

**② 但 module 69 自己定义的方法只有这些（脚本枚举结果）：**
```
constructor, newWindow, resetWindow, closeWindow, addOne(来自 module 3)
```
→ **module 69 没有 `startLock` 方法。**（实测：`methods.includes("startLock") === false`）

**③ 真正定义 `startLock` 的是屏幕锁控制器（module 40）：**
```js
constructor(){ ... this.startLock = this.startLock.bind(this); this.closeWindow = this.closeWindow.bind(this) }
startLock(){ /* 逐屏创建 screenLock_N 全屏窗口 */ }
```

### 结论

`this.closeWindow()` 能成功，是因为 module 69 **确实有** `closeWindow`；
而 `this.startLock()` 必然抛 `TypeError`，因为该对象上**根本不存在**这个方法。

> 这是**代码层面的确定性缺陷**（把锁屏控制器的调用误写进窗口管理器），
> 不是"偶发 bug"也不是"集控策略没配全"。
> 因此：**只要官方不修这段代码，关屏保就永远不会自动锁屏。**
> 这解释了为什么用户按 Alt+F4（或点屏幕）能直接回到桌面。

**这个发现的实际意义**：用户**不需要**去"绕过"锁屏——锁屏本来就因官方缺陷没生效。
反过来说，如果哪天官方修复了这段代码（让 `startLock` 能被正确调用），
屏保就可能真的变成"关掉即锁屏"。**这一点需要在方案里预留应对**（见第五节的守卫模块）。

## 三、屏保数据契约（[实证] 逐字解码自 `screensaver.js`）

原对话在参数解释上有两处错误，以下是**从渲染器源码逐字解码**的准确版本：

```js
var D = ["contain", "cover"];           // pictureSizeType 映射表
var F = window._ACCEPT_DATA;            // 数据总线

function e(data) {                       // screensaverMessage 处理函数
  y(data.materialSource || "");          // 素材来源文案（默认空串）
  f(1000 * (data.switchInterval || 15)); // ★ 单位=秒，乘 1000 变毫秒，默认 15 秒
  x(D[data.pictureSizeType || 0]);       // ★ 0=contain（留边） 1=cover（铺满）
  s(data.imageList.map(p => p.replace(/\\/g, "\\")) || []);   // 图片路径（反斜杠转义）
  C(data.textList || []);                // 图文条目 [{content, provenance?}]
}
```

| 字段 | 类型 | 默认 | 准确含义 |
|---|---|---|---|
| `materialSource` | string | `""` | 底部"素材来自 X"，空串不显示 |
| `switchInterval` | number | `15` | **秒**（渲染器内部 ×1000） |
| `pictureSizeType` | number | `0` | **0=contain 留边完整显示；1=cover 裁剪铺满** |
| `imageList` | string[] | `[]` | 图片路径数组 |
| `textList` | object[] | `[]` | `{content, provenance?}` |
| `screensaverTransitionList` | number[] | — | 长度**必须**=`imageList.length`，值域 **0..6** |

### 关于时间/日期 [实证]

```js
var Y = function(e) {  // 时间钩子
  ... l(e.format("HH:mm")), _(e.format(t)), u(e.format("dddd"))   // t 默认 "YYYY/MM/DD"
};
useEffect(function(){ return n(), b = setInterval(function(){ n() }, 6e4), ... }, [])
//                                          ^^^^^^^^^^^^^^^^^^^^^^^ 每 60 秒刷新
```
→ 屏幕上 78px 的大时间、`YYYY/MM/DD` 日期、星期几**全部由网页动态渲染**，
**不是图片自带的**。所以替换图片不会影响时间显示。

### `playMode` 不存在 [勘误]

全量正则检索 `main.js` 与 `screensaver.js`：**均未出现 `playMode`**。
轮播顺序由渲染器内部逻辑决定，没有这个配置字段。
（如果日志里真出现了 `playMode`，那可能是其它模块或更新版本的字段，但**在 v1.2.7 的屏保链路上不存在**。）

## 四、`app.asar` 怎么打开（原对话给的步骤有问题）

原对话建议 `npm install -g asar`，但 **`asar` 包已废弃**，现在应使用 `@electron/asar`。

### 正确做法（本机实测可用的版本）

```bash
# 1. 装工具（注意新包名）
npm install @electron/asar

# 2. 解包
node node_modules/@electron/asar/bin/asar.mjs extract app.asar ./app

# 3. 改文件
#    app/public/screensaver.html
#    app/public/screensaver.js

# 4. 重新打包
node node_modules/@electron/asar/bin/asar.mjs pack ./app ./app_new.asar
```

> ⚠️ 本机实测两个坑：
> 1. `asar` 的 CLI 入口是 `bin/asar.mjs`（不是 `bin/asar.js`），直接 `node bin/asar.js` 会报 MODULE_NOT_FOUND。
> 2. 若 `/tmp` 为 `noexec`，7z 等二进制必须放在可执行目录，且 npm 需要 `--cache` 指向可写目录。

### 但：**改 asar 通常不是最优解** [勘误]

原对话称改 `app.asar` 是"目前唯一能深度自定义屏保的方法"，这**不准确**：

| 方案 | 能否达到目的 | 风险 |
|---|---|---|
| **① 直接换图片文件**（用户的 `.bat` 路线） | ✅ 最简单 | 低。集控重新下发会覆盖 |
| **② 注入式覆写数据**（hook `screensaverMessage`） | ✅ 最灵活 | 中。需注入能力，但不动官方文件 |
| **③ 改 `app.asar`** | ✅ | **高**：`Verify.json` 可能有完整性校验、`BootConfig.needGuard:true` 有守护进程、升级即被覆盖、违反 EULA |

→ 用户当前需求（换图）用 **方案 ①** 就够了；若要改**行为**（比如改停留时长、关掉级联），
**方案 ②** 更优。**方案 ③ 是下策**。

## 五、用户脚本反复失败的真正原因（技术复盘）

对话里用户运行 `换屏保.bat` 报错：
`Missing ']' after array index expression` / `Unexpected token '$(...` / `The string is missing the terminator`

### 根因 [实证]

在 `.bat` 里用 `^\` 续行内嵌多行 PowerShell 时，**CMD 会先做自己的解析**：

1. `%` 被 CMD 当作环境变量起始符 → `$sourceFiles[$i % $sourceFiles.Count]` 里的 `% $sourceFiles.Count]` 被 CMD 吃掉/破坏。
   这就是 `Missing ']' after array index expression` 的直接来源。
2. `^` 续行 + 双引号嵌套 → CMD 的引号配对规则与 PowerShell 不同，传给 PS 的字符串被截断
   → `The string is missing the terminator`。
3. `$(` 出现在 `$(Get-Date ...)` → 若外层引号没配好，PS 收到残缺 token → `Unexpected token '$(...`。

### 正确解法

**不要把 PowerShell 内联在 `.bat` 里**。三个稳妥选项（按推荐度）：

| 方案 | 说明 | 推荐度 |
|---|---|---|
| **A. 纯 CMD 实现** | 只用 `xcopy`/`copy`/`for`，无 PS、无转义问题 | ⭐⭐⭐⭐⭐ 用户当前需求够用 |
| **B. 生成临时 `.ps1`** | `> temp.ps1` 写文件再 `powershell -File temp.ps1`，**完全绕开 CMD 转义** | ⭐⭐⭐⭐ 逻辑复杂时更佳 |
| **C. 直接给 `.ps1`** | 用户需处理执行策略，体验差 | ⭐⭐ |

→ 本仓库提供了 **方案 A 的修正版**（`scripts/换屏保.bat`）和 **方案 B 的可靠版**（`scripts/换屏保_PS版.bat`）。

## 六、结论小结

1. **用户的目标（换屏保图）用纯 CMD 脚本即可稳定完成**，不需要碰 `app.asar`、不需要 PowerShell 内联。
2. **原对话有几处参数解释错误**（`pictureSizeType` 含义反了、时间不是图片写死的、`playMode` 不存在），
   已在上表逐条勘误，以本机真实代码为准。
3. **`this.startLock is not a function` 是确定性代码缺陷**（module 69 调用了自己不存在的 `startLock`），
   不是随机 bug。当前因此**关屏保不会锁屏**。
4. **用户真正需要警惕的是相反情况**：若官方修好这段代码，屏保就会变成"关掉即锁屏"。
   本仓库的 `src/hooks/lockCascadeGuard.js` 正是为此准备的**可控开关**。
