# 图形配置界面

> 不想手改 JSON？双击启动界面，用鼠标配置屏保，一键预览效果。

---

## 一、启动

**exe 版（推荐）**：双击 `AuraScreensaver.exe`，UAC 弹窗点「是」。
**脚本版**：双击 `scripts\配置屏保.bat`。

两种方式都**不需要 Node.js** —— 界面是 PowerShell + WinForms 实现的。

> ⚠️ 首次启动会请求管理员权限，这是**必须**的：希沃管家装在 `Program Files (x86)`，
> 不提权无法写入 `app.asar`，会报「对 xxx\app.asar.bak 的访问被拒绝」。

## 二、界面按状态显示（刻意做得很克制）

不该点的按钮不会出现在你面前。只有两种状态：

### 状态一：未安装（未注入）

```
┌────────────────────────────────────────┐
│ 尚未安装（未注入）                       │
│ 安装目录：C:\Program Files (x86)\...    │
│ 希沃管家：未运行                         │
│                                        │
│        ┌────────────────────┐          │
│        │      一键安装       │          │
│        └────────────────────┘          │
└────────────────────────────────────────┘
```

**整个界面只有一个按钮**，配置项全部隐藏（不是置灰，是根本不显示）。

点「一键安装」后会自动依次完成：

1. 定位希沃管家（支持 `SeewoService_<版本号>` 这种版本目录）
2. **结束希沃管家进程** —— 避免文件被占用写不进去
3. 备份 `app.asar` → `app.asar.bak`
4. 注入，并**回读校验**注入标记确实存在
5. **重新启动希沃管家**
6. 轮询日志确认出现「命令桥已启动」—— 到这一步才算真正成功

### 状态二：已注入

```
┌────────────────────────────────────────┐
│ 已注入 ✓  屏保行为由本工具控制           │
│ 安装目录：...        希沃管家：运行中    │
├────────────────────────────────────────┤
│ ☑ 启用屏保                              │
│ ☐ 关闭屏保后自动锁屏                     │
│ ☑ 使用自定义图集                        │
│   素材来源 [________]  间隔 [15] 秒      │
│   图片适配  ○留边完整显示  ○裁剪铺满      │
│   图片列表 / 图文条目 / 转场效果          │
├────────────────────────────────────────┤
│ [ 保存并预览 ]   [ 卸载还原 ]   查看日志  │
└────────────────────────────────────────┘
```

只有三个操作入口：**保存并预览**、**卸载还原**、**查看日志**（链接形式）。
「卸载还原」同样会自动结束并重启希沃管家。

### 校验是实时的

输入非法值时（例如切换间隔填 `1.5`），保存会被拒绝，并**精确定位到对应输入框**高亮提示：

```
[override.switchInterval] switchInterval 必须是正整数（秒，单位=秒；渲染器内部会 ×1000）（实际值: 1.5）
```

校验规则直接复用 `src/config/schema.js`，**与加载器读取时的规则完全一致** —— 不会出现「界面让存、程序不认」。

## 三、★ 关于「立即预览」的一个重要设计决定

**手动预览会绕过「启用屏保」开关的限制。**

也就是说：即使你把屏保**关掉了**，点「立即预览」照样能唤起屏保。

理由很实在——你要看的是**配置效果**。如果关掉屏保就再也预览不了，那这个按钮在有意义的场景下恰好是失效的（"我关了屏保，但我想先看看这套图好不好看"）。

区分清楚两件事：

| | 含义 | 受 `screensaverEnabled` 影响 |
|---|---|---|
| **自动/集控下发** | 学校集控推来的屏保指令 | ✅ 关闭时一律拦截 |
| **手动预览** | 你在界面上主动点的那一下 | ❌ 不受影响，永远可用 |

## 四、预览是怎么真正生效的（架构说明）

这里是唯一有点绕的地方，值得说清楚。

**问题**：图形界面是一个独立的 Node HTTP 进程，而屏保窗口由**希沃管家主进程**里的 webpack 模块 120 渲染。跨进程没法直接调用对象方法。

**方案**：命令文件桥。

```
┌──────────────┐  写 command.json   ┌──────────────────────┐
│  浏览器界面   │ ──────────────────▶ │  希沃管家主进程        │
│  (HTTP 服务)  │                     │  (注入的 loader)       │
│              │ ◀────────────────── │  每 700ms 轮询一次     │
└──────────────┘  写 command-result   └──────────────────────┘
```

1. 界面点「立即预览」→ 后端把 `{seq, cmd:'preview'}` 写入
   `%APPDATA%\seewo\AuraScreensaver\command.json`
2. 注入在管家里的 loader 每 700ms 轮询一次，读到新 `seq` 就执行
3. 执行完把结果写入 `command-result.json`
4. 后端读到对应 `seq` 的结果 → 返回给界面

**为什么用文件而不是 socket / 命名管道**：文件方式在任意用户权限下都可用，出问题时能直接打开文件看内容，排查成本最低。同一个 `seq` 只执行一次，不会因为轮询重复触发。

### 因此失败时你会看到明确的提示

| 提示 | 真实原因 |
|---|---|
| `E_PREVIEW_NO_BRIDGE` | 命令发出了，但**管家进程没在跑**（或没注入）——loader 不在，没人消费命令 |
| `no-controller` | 注入成功了，但模块 120 没拿到（版本结构变了） |
| `empty-image-list` | 配置里一张图都没有，预览没有内容可显示 |
| `no-payload` | `override` 为空，且还没收到过集控下发的数据 |

**绝不谎报成功** —— 这些是真实状态，不是"大概应该好了"。

## 五、安全设计

- 服务只监听 **127.0.0.1**（传入其它地址会被强制拒绝），局域网内其它机器访问不到
- 零 npm 依赖，只用 Node 内置模块 —— 不会因为装依赖引入供应链风险
- 前端**零 CDN**，所有资源本地提供 —— 无外网也能正常显示
- 配置写入是**原子的**（临时文件 + rename），并保留 `.bak`
- 端口被占用会自动 +1，不会启动失败

## 六、常见问题

**Q：双击提示「未检测到 Node.js」？**
装 Node.js LTS，安装时勾选 Add to PATH，装完**重新打开**窗口（PATH 变更对已开窗口无效）。

**Q：浏览器没自动打开？**
手动访问 `http://127.0.0.1:8899`。若端口被占用会自动换成 8899+，请看你启动的那个命令行窗口里打印的实际地址。

**Q：点了「立即预览」没反应？**
按提示顺序查：
1. 顶部「注入状态」是否为「已注入」。
2. 希沃管家是否正在运行（关掉管家 = loader 不在 = 命令没人执行）。
3. `%APPDATA%\seewo\AuraScreensaver\command-result.json` 是否存在、内容是什么。

**Q：改了配置要重启管家吗？**
不需要。用界面保存后点预览即可；界面的保存走的是同一份 `config.json`，
且 loader 支持 `reloadConfig`（免重启）。若你手改了 JSON，重新点一次保存或预览即可。

**Q：界面上「图片列表」要填什么路径？**
Windows 绝对路径，例如 `C:\Users\你的用户名\Pictures\a.jpg`。建议用正斜杠 `C:/Pictures/a.jpg` 也可以，两者都支持。

## 八、安装目录到底在哪（重要）

希沃管家的真实安装布局是这样的（**注意中间有版本号目录**）：

```
C:\Program Files (x86)\Seewo\SeewoService\SeewoService_1.2.8.2833\SeewoServiceAssistant\
  ├─ SeewoServiceAssistant.exe
  └─ resources\app.asar      ← 本工具要改的就是这个文件
```

`SeewoService_1.2.8.2833` 这个**版本号目录每次升级都会变**，所以：

- 不能写死路径，必须用通配符 `SeewoService_*` 搜索
- 早期版本的工具只试了 `...\Seewo\SeewoServiceAssistant`（少了 `SeewoService\<版本>` 这一层），
  于是报「找不到路径」。已修复。

现在的定位顺序：

1. **正在运行的管家进程**给出的真实 exe 路径（最准，版本号再变也能命中）
2. `Program Files` / `Program Files (x86)` 下 `Seewo\SeewoService\SeewoService_*\SeewoServiceAssistant` 通配符搜索
3. 其它盘符（D:/E:/F:）同样的通配符
4. 注册表卸载项里的 `InstallLocation` / `DisplayIcon`
5. 都不行 → 弹文件夹选择框，手动指定（选到上层目录也能自动往下找到）

### 自己确认目录对不对

点界面上的「诊断」按钮，会直接列出：

- 安装目录（是否找到）
- `app.asar` 是否存在、`.bak` 是否存在
- `command.json` / `command-result.json` 是否生成
- 加载器日志是否存在
- 希沃管家进程是否在运行

> 判断是否注入成功的关键证据：**有没有 `command-result.json`**。
> 只有 `command.json` 而没有 `command-result.json`，说明命令发出去了但没人消费 ——
> 也就是**注入没生效**（或管家没在运行）。

### 顺带一个发现

`%APPDATA%\seewo\SeewoAbility\screen_saver.json` 以及同目录下的
`screen_saver\` 文件夹，是学校集控下发屏保素材的缓存位置（那些哈希命名的文件就是图片）。
本工具不去改它 —— 因为集控随时会重新下发覆盖；我们是在**主进程拦截指令**这一层做事，
这样无论集控怎么推，行为都由你的配置决定。

## 九、安装失败怎么看原因

「一键安装」失败时，程序会自动写一份**详细日志**，两个位置都会尝试写：

```
<exe 所在目录>\AuraScreensaver-install.log
%APPDATA%\seewo\AuraScreensaver\install.log
```

弹窗里也会直接显示日志路径。日志包含：

- 是否真的拿到了管理员权限、当前用户名
- 实际使用的安装目录
- 对 `resources` 目录的**写权限测试结果**
- 失败时记录该目录的 **ACL 原文**（能直接看出是否被设了拒绝）
- 每一步的结果（结束进程 / 写临时文件 / 替换 / 重启）

### 写入流程是原子的

为了避免「写到一半被中断」导致 `app.asar` 变成坏文件：

1. 先在**同一目录**写出 `app.asar.new`
2. **回读校验**临时文件（能解析 asar + 含注入标记）
3. 备份：优先把 `app.asar` **重命名**为 `app.asar.bak`（原子），失败才退回复制
4. 用 `File.Replace` **原子替换** `app.asar`
5. 任何一步失败都会**从备份回滚**

最坏情况是「没变化」，不会出现「改坏了打不开」。

### 访问被拒绝的三种真实原因

| 原因 | 判断方法 | 处理 |
|---|---|---|
| 不是管理员 | 日志里 `管理员权限: False` | 右键 exe → 以管理员身份运行 |
| 目录有**显式 DENY** ACL（防篡改） | 日志 ACL 原文出现 `(DENY)` | 程序自动 `takeown` + `icacls /reset` 修复 |
| 杀软 / 受控文件夹访问拦截 | 权限测试失败但 ACL 正常 | 把希沃目录或本程序加入白名单 |

程序动手前会先做**写权限测试**，不可写就先尝试修 ACL，修不好直接报明确原因，
不会留下半成品文件。

### 关于希沃自动重启

安装时会先结束 `SeewoServiceAssistant` 和 `ShowTaskBarTool`，并等待真正退出。
如果检测到**被自动拉起**（某些部署有守护进程），日志会记录：

```
注意：检测到管家被自动重新拉起（这会让 app.asar 持续被占用）
```

这种情况下写入可能仍失败，日志会体现出来。可尝试先在托盘里「退出」希沃，
立刻安装；或改用 `scripts\安装.bat`（命令行版，有交互确认）。

## 十、实测确诊：希沃有自我保护，会拦截写入

### 现象

管理员权限、目录 ACL 正常，但写入仍然「访问被拒绝」。

### 日志证据（真实环境）

```
管理员权限: True
当前用户: DESKTOP-QS6GS2E\seewo

当前 ACL:
  ...\resources  NT SERVICE\TrustedInstaller:(I)(F)
                 NT AUTHORITY\SYSTEM:(I)(F)
                 BUILTIN\Administrators:(I)(F)      <-- 管理员是「完全控制」
                 BUILTIN\Users:(I)(RX)

takeown 异常: 错误: 拒绝访问。
icacls /reset 异常: ...拒绝访问。
ACL 修复后是否可写: False
```

### 判断

。`BUILTIN\Administrators` 已经是 **(F) 完全控制**，理论上管理员可以随便写
2. 但**连 `takeown` 都被拒绝** —— 这已经超出 ACL 的范畴了
3. 结论：有**内核级过滤驱动**在拦（防篡改设计），ACL 形同虚设

换句话说：**这不是权限没配对，而是希沃主动阻止第三方改它的文件**。
改 ACL、提权、用管理员跑，都不会有用。

### 程序现在的应对

1. 先只读生成补丁并在 `%TEMP%` 校验（不碰受保护目录）
2. 写权限测试 → 不行就尝试 ACL 修复（通常无效，但会记录证据）
3. **询问是否临时停止希沃相关服务**，停掉后重试，结束后自动恢复
4. 仍不行 → **把打好补丁的 `app.asar` 导出到桌面**，并给出三种绕过办法

### 三种绕过办法

| 办法 | 说明 |
|---|---|
| 先退出希沃再装 | 托盘右键退出 + 结束所有希沃进程，保护可能随之卸载 |
| 安全模式覆盖 | 重启进安全模式（不加载第三方驱动），把桌面导出的文件覆盖过去 |
| 找管理员关闭保护 | 最干净，但需要学校配合 |

> 安全模式覆盖的路径（日志里也会打印）：
> `C:\Program Files (x86)\Seewo\SeewoService\SeewoService_<版本>\SeewoServiceAssistant\resources\app.asar`
> 覆盖前记得先备份原文件。
