# 深度配置屏保 + 关闭屏保

> 💡 **不想手改 JSON？** 双击 `scripts\配置屏保.bat` 打开图形界面，可视化配置并一键预览。
> 详见 [图形界面.md](图形界面.md)。本文是底层配置项的完整参考。
>
> 本文对应你的需求："能不能实现深度配置屏保功能和关闭"。
> **可以**，方案参考 HugoAura-Enhanced 的注入式思路，但做得更简单、更安全。

---

## 一、能做什么

修改配置文件 `%APPDATA%\seewo\AuraScreensaver\config.json` 即可控制：

```json
{
  "screensaverEnabled": false,
  "lockCascadeOnClose": false,
  "override": {
    "materialSource": "我的班级",
    "switchInterval": 30,
    "pictureSizeType": 1,
    "imageList": ["C:\\\\pics\\\\1.jpg", "C:\\\\pics\\\\2.jpg"],
    "textList": [{ "content": "今日值日：张同学", "provenance": "班务" }],
    "transitionList": [0, 3, 6]
  },
  "logLevel": "info"
}
```

| 配置项 | 作用 |
|---|---|
| `screensaverEnabled: false` | **★ 关闭屏保** —— 集控再下发也不再弹出 |
| `lockCascadeOnClose: false` | 关闭「关屏保 → 自动锁屏」级联（默认已关） |
| `override.materialSource` | 底部"素材来自 X"文案 |
| `override.switchInterval` | **切换间隔（秒）**，正整数；渲染器内部 ×1000 |
| `override.pictureSizeType` | `0`=contain 留边完整显示 / `1`=cover 裁剪铺满 |
| `override.imageList` | 自定义图片路径数组 |
| `override.textList` | 图文轮播条目 `{content, provenance?}` |
| `override.transitionList` | 转场编号数组，长度须=图片数，值域 **0..6** |

改完配置**重启希沃管家**生效，无需重新注入。

## 二、安装步骤

### 准备
1. 安装 [Node.js](https://nodejs.org/zh-cn/download)（LTS 版，安装时勾选 "Add to PATH"）
2. 确认希沃管家已安装

### 安装
双击 `scripts\安装.bat`，按提示操作。

它会：
1. 自动定位希沃管家目录
2. 备份 `app.asar` → `app.asar.bak`（**已存在则保留，不覆盖**）
3. 调用 `tools/patch-asar.js` 注入
4. 写入默认配置文件（已存在则保留）

### 卸载还原
双击 `scripts\卸载.bat`，从 `.bak` 完整还原。

## 三、技术原理（为什么可行）

### 3.1 注入点只有两处

官方 `app/main.js` 是 webpack 4 数组式 bundle：

```js
!function(e){ var t={}; function n(s){ ... e[s].call(r.exports,r,r.exports,n) ... }
  n.m=e,n.c=t,n.p="",n(n.s=140) }([ module0, module1, ... ]);
```

**注入 ①** —— 在 bootstrap 尾部把 webpack require 暴露出来：
```diff
- n.p="",n(n.s=140)}([
+ n.p="",global.__AURA_REQ__=n,n(n.s=140)}([
```

> ⚠️ 上面这版是**我最初的方案，存在一个真实缺陷**：如果官方入口 `n(n.s=140)` 自身抛异常，
> 整条表达式语句求值失败 → 末尾 loader 根本不会执行，**注入完全落空且无声无息**。
> 实测对比（入口抛异常场景）：原方案 LOADER marker = `undefined`，现方案 = `true`。

**实际采用的注入 ①（已修正）** —— 把入口调用一并包进 try/catch：

```js
n.p="",global.__AURA_REQ__=n,(function(){
  try { return n(n.s=140); }
  catch (__auraEntryErr) {
    try { setTimeout(function(){ throw __auraEntryErr; }, 0); } catch (e) {}
    global.__AURA_ENTRY_ERROR__ = __auraEntryErr;   // 保留可观测性
    return undefined;
  }
})()
```

错误异步重抛，**不改变官方「入口异常即终止」的语义**，但保证 loader 仍能安装。

**注入 ②** —— 在文件末尾追加自包含 loader。

之后即可拿到**官方模块单例**：
```js
const req = global.__AURA_REQ__;
req(120)  // 屏保控制器（有 onMessage）→ 包装它就能关闭/改写屏保
req(69)   // 窗口管理器（close 回调级联 startLock）→ 包装它就能切断级联
```

### 3.2 与 HugoAura 的对比

| | HugoAura | 本工具 |
|---|---|---|
| 拿模块的方式 | 劫持 `window.webpackJsonp` + `eval` 模块源码 + 特征匹配 | **只捕获 webpack require**，不 eval |
| 杀软风险 | 较高（eval + 特征匹配） | 低 |
| 误伤风险 | 可能替换错模块工厂 | 无（不替换工厂，只加一个引用） |

### 3.3 为什么重打包不会触发校验

`Verify.json` 共 43 项，只包含：

- 36 个 `.dll`
- `SeewoServiceAssistant.exe`、`ShowTaskBarTool.exe`
- `resources/assets/dlls/` 下 3 个 dll

**`app.asar` 不在清单内** → 重打包可行。

> ⚠️ 本工具**绝不修改 .exe**（它在校验清单内）。改了会导致校验失败。

## 四、安全设计

1. **完整备份**：`app.asar.bak`，且**已存在时不覆盖**（保护最原始的备份）
2. **失败自动还原**：重新打包失败会自动从备份还原
3. **语法自检**：注入后的 `main.js` 先做语法检查，不通过则中止且不写任何文件
4. **幂等**：重复运行会检测到已有注入并提示，不会叠加
5. **loader 防御式**：全程 `try/catch`，即使模块定位失败也**只记日志、放行官方行为**，绝不阻断管家启动
6. **不动 .exe / 被校验的 dll**

## 五、风险与注意

| 风险 | 说明 | 应对 |
|---|---|---|
| **希沃升级会覆盖** | 升级后 `app.asar` 被替换，注入失效 | 重新运行 `安装.bat`（配置会保留） |
| **版本结构变化** | 新版 bundle 结构不同会导致锚点找不到 | 工具会**安全退出**并提示，不会破坏原文件 |
| **学校管理策略** | 修改集控行为可能违反校方规定 | ⚠️ 请自行确认合规，仅用于个人设备自管理 |
| **EULA** | 修改软件文件可能违反许可协议 | 同上 |
| **校园网重推** | 集控重新下发屏保图片 | 配置里的 `override.imageList` 会覆盖云端数据 |

### 未能验证的部分（诚实说明）

**真机运行未验证。** 原因：本环境是 Linux，希沃管家的 `main.js` 依赖 Windows 原生模块
（`windowsApiFfi.dll` / `KeyBoardHookFfi.dll` / `ffi_bindings.node`）才能构造出模块实例。

我用桩替代这些模块试跑，结果是：注入本身生效（`global.__AURA_REQ__` 成功捕获），
但 `req(120)` 等因原生依赖缺失而构造失败，此时 loader **按设计降级**：
```
[WARN] 取屏保控制器(120)失败: ...
[WARN] 未找到屏保控制器 onMessage —— 跳过屏保拦截（放行官方行为）
[INFO] aura-screensaver 已安装: {"hook":false,"guard":false}
```

→ 这验证了**安全降级路径**正确，但 `req(120)` 在真机（有原生 DLL）上能否成功返回实例，
**必须在 Windows 真机上验证**。请在测试机先跑一次，确认日志出现：
```
[INFO] 屏保控制器已包装 (onMessage hook 已安装)
```

## 七、常见问题

**Q: 安装后没效果？**
A: 1) 重启希沃管家；2) 查看 `%APPDATA%\seewo\AuraScreensaver\aura-screensaver.log`；
3) 若日志显示"未找到屏保控制器"，说明该版本结构不同，请反馈。

**Q: 怎么确认安装成功？**
A: 运行 `node tools/patch-asar.js --dry-run --target "<你的路径>\app.asar"`，
若提示"已存在注入标记"即为成功。

**Q: 会不会把设备搞坏？**
A: 有 `.bak` 备份 + 失败自动还原 + 语法自检三重保护。最坏情况用 `卸载.bat` 还原。
但**任何修改官方文件的操作都有风险**，建议先在非关键设备上验证。
